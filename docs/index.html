Skew Resilient Real Time Streaming Vector Search Database

Authors: Arjuna Bazaz and Liu

Carnegie Mellon School of Computer Science

Summary

We are going to build a real time streaming GPU accelerated parallel Inverted File (IVF) for vector search that handles real time inserts and deletes. We are going to optimize for high workload skew, with write heavy and delete heavy workloads.

Background

Vector search is the process of finding the vector within a database that has the smallest distance to another input vector. This is usually done by calculating the L2 distance (euclidean distance) of the two vectors. However, unlike 1-dimensional datasets, the high dimensional nature of the data makes binary search impossible. In addition, approach used for low dimensional data such as kD trees do not work due to the high dimensions leading to much more overlap with blocks.

One solution to this is an inverted file (IVF). IVF used density based clusters to split the dataset into smaller sections. An incoming vector first determines which cluster to visit, then searches through the cluster for the nearest neighbor. This greatly speeds up nearest neighbor search. This is usually implemented by assigning each cluster a block of memory and loading it into shared memory for each streaming multiprocessor, with each SM handling queries to a specific cluster. This makes inserts impractical in real time. Typically, systems batch inserts and updated them later, assuming that eventual consistency is okay.

Our project aims to add real time streaming of inserts, deletes, and centroid updates.

Parallelism is very valuable for systems like this since handling concurrent queries is essential for modern large systems. The vector search is very memory bound, so efficiently handling data loading and streaming is very important. When adding in writes and deletes, handling parallel writes in also important for the same reason. Since the data often writes and deletes to the same cluster blocks, synchronyzation is also important.

Vector search is extremely useful for doing searches an filters on complex data. Complex data (such as language) is often encoded as vectors. IVF is useful for determining things like, "what is the closest sentence in this book semantically to this other sentence." A solution that can handle extreme skew is valuable for problems don't involve a premade corpus of vectors that are operated on consistently.

The Challenge

This project is difficult to parallelize while still preventing heavy memory bandwidth throttling. It has a high memory across to computation ratio, which needs to be worked around is any solution. A typical system will load an entire set of clusters into shared memory for caluclations. A incoming query will get assigned to a specific SM. However, when inserts are streamed, it causes issues since the clusters are typically set in fixed blocks, and adding anything would lead to the recomputation of the block. Our proposed solution is to create blocks or pages of memory that are loaded into shared memory and contain a fixed size portion of a cluster. This introduces parallelism problems, though, as the threads need to ensure that they don't create new blocks for the same cluster even when that cluster is noncontiguous. Writes also need to be coordinated with a write buffer. This buffer needs to prevent threads from grabbing the same write, will also ensures that they are fast. To do this, the write buffer must be a lock free queue.

In addition, our database is meant to be optimized for high workload skew. This raises many new pararallelization problems. Firstly, high write workloads can cause contention for a single write buffer, requiring further workload partition. Workload partition brings its own problems, such as workload imbalance that requires its own solutions. High write concentration also means that threads contend for memory slabs for theirs writes.

Lastly, frequent writes and deletes mean that centroid will drift over time and need to be recomputed. This is difficult to parallelize since the recomputation process does not exhibit much locality and must be performed serially. In addition, the process of reassigning vectors to centroids leads to read/write conflicts with other threads performing queries. This requires a new layer of synchronyzation during centroid reshuffling.

Goals and Deliverables

Plan to Achieve

  • Create IVF that handles real time streaming while maintaining sequential consistency.
  • Achieve a speedup of 5x or more vs naive recomputation for inserts.
  • Acheived reduced memory overhead on high delete workloads compared to FAISS
  • Acheive improved performance compared to FAISS on workloads with less than 70% queries (30%+ writes/deletes)

Hope to Achieve

  • Supported centroid recalculation. Measured by improved accuracy of nearest neighbor compared to naive approach.
  • Improve performance on workloads with data size > 32 GB by handling mutli-GPU coordination.

Evaluation Plan

We plan to measure our performance based on benchmarks with variable data size, centroid count, workload skew, and operation skew. We hope to answer the question of whether high workload skew degrades performance of existing approaches and whether a skew focused approach can improve this while maintaining consistent performance on high query workloads.

Platform Choice

Our project uses CUDA for GPU acceleration and coordination. For communication across GPUs, we plan to use MPI, although NCCL is an alternative that may be considered.
